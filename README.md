# afb-yolo13

Baseline + architectural improvement experiments untuk **deteksi *Mycobacterium tuberculosis* (AFB / bacilli)** dengan **YOLOv13** pada dataset **Tuberculosis6208** (phone-camera microscopy, Makerere).

## Dataset

- **Source:** [Tuberculosis6208 — Makerere Automated Lab Diagnostics Database](https://zenodo.org/record/...) (Pascal-VOC format).
- **N pairs:** 1265 image+XML.
- **Class:** 1 (`bacilli`, mapped dari label XML `TBbacillus`).
- **Split:** Chen et al. IJAI 2024 — **1024 train / 140 val / 101 test**, deterministic shuffle `seed=42` (sama dengan eksperimen YOLOv12 untuk apples-to-apples comparison).
- **Local path:** `D:/project/yolov12/Tuberculosis6208/tuberculosis-phonecamera/`

## Setup

YOLOv13 fork (iMoonLab) harus sudah di-install editable. Asumsi fork ada di `D:/Project/yolov13/`:

```powershell
# (sekali saja) install YOLOv13 dari local fork
pip install -e D:/Project/yolov13

# install dependency tambahan
pip install -r requirements.txt
```

## Workflow baseline (seed=42, 1 run)

### 1. Build split

```powershell
python scripts/build_chen_split.py `
    --src "D:/project/yolov12/Tuberculosis6208/tuberculosis-phonecamera" `
    --out "D:/datasets/tb_chen_split" `
    --seed 42
```

Output:
```
Image+XML pairs: 1265 (target 1265)
Split: train=1024  val=140  test=101  seed=42
Wrote D:/datasets/tb_chen_split/data.yaml
```

### 2. Train baseline YOLOv13s

```powershell
python scripts/train_baseline.py `
    --data "D:/datasets/tb_chen_split/data.yaml" `
    --model yolov13s `
    --seed 42 `
    --epochs 60 `
    --imgsz 640 `
    --batch 16 `
    --project "D:/runs/afb_yolov13" `
    --name yolov13s_seed42_60ep
```

Pretrained `yolov13s.pt` auto-download dari iMoonLab release.

### 3. Diagnose baseline (untuk decide arsitektur improvement)

```powershell
python scripts/diagnose_baseline.py `
    --ckpt "D:/runs/afb_yolov13/yolov13s_seed42_60ep/weights/best.pt" `
    --data "D:/datasets/tb_chen_split/data.yaml" `
    --split val `
    --imgsz 640
```

Output:
- per-IoU mAP (0.5, 0.6, 0.7, 0.8, 0.9)
- FP composition (near / close / far / would-be-TP)
- FullPAD_Tunnel gate values (cek HyperACE pathway aktif atau α-trap)
- per-scale recall (P3/P4/P5)
- recommendation tag (e.g., "fix-localization", "fix-fp", "arch-add-p2")

## Architectural improvement (next step)

Setelah baseline diukur, target arch novelty (lihat diagnose output):
- Diagnose-driven: kalau P3 recall rendah → P2 head; kalau FP-near tinggi → localization (NWD / Inner-CIoU); kalau FullPAD gates dead → arch redesign.
- Kandidat (kombinasi narrow, bukan first-claim): Scale-Conditioned Hyperedge, Spatial-gated FullPAD, NWD loss, small-obj copy-paste.
